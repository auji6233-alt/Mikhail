# План: напоминания клиентам о завтрашней записи

## 1. Задача

Сейчас напоминаний нет вообще — клиенты просто не предупреждаются о записи заранее (сам подтвердил в интервью). Это не «отнять время у ручной работы», а закрыть дыру, которая сегодня открыта.

## 2. Вход

Таблица `Booking` в Postgres (через Prisma) — записи со статусом `CONFIRMED`, у которых `startAt` приходится на завтра.

Пример строки входа (выдуманные данные):
```
id: cktz...          masterId: <Анна>      serviceId: <Маникюр>
startAt: 2026-09-16T12:00:00Z   endAt: 2026-09-16T13:30:00Z
clientName: "Мария Иванова"     clientPhone: "+7 900 111-22-33"
telegramChatId: 555111222       remindedAt: null
status: CONFIRMED
```
`telegramChatId` — новое поле (сейчас его нет, добавляем сегодня). У записей с сайта (`/book`) оно всегда `null` — это ожидаемо, не баг.

## 3. Выход

Сообщение в Telegram от бота — клиенту, у которого известен `telegramChatId`. Плюс короткий отчёт в консоли после запуска. Ничего в файл не сохраняется.

## 4. 👀 Образец выхода

**Сообщение клиенту в Telegram** (реальный текст, который получит человек):
```
Здравствуйте, Мария! Напоминаем: завтра, 16 сентября, в 15:00 у вас запись
на «Маникюр» к мастеру Анна. Если планы изменились — напишите нам здесь же.
```

**Отчёт в консоли после запуска:**
```
Напоминания на 16.09.2026 (записей на завтра: 3)

✅ Отправлено: Мария Иванова, 15:00, Маникюр у Анны (chat 555111222)
✅ Отправлено: Пётр Сидоров, 17:30, Стрижка у Олега (chat 555333444)
⏭️  Пропущено (нет Telegram-чата — запись с сайта): Ольга Кузнецова, 12:00, Педикюр у Анны

Итог: 2 отправлено, 1 пропущено, 0 ошибок
```

## 5. Пайплайн по шагам

| Шаг | Что делает | Чем | Выход шага |
|---|---|---|---|
| 1 | Достаёт из `Booking` записи на завтра со статусом `CONFIRMED` и `remindedAt = null` | Postgres (Prisma) | Список записей |
| 2 | Для записей с `telegramChatId` — собирает текст напоминания по шаблону | Локальный код (без ИИ — фиксированный шаблон, AssemblyAI/OpenRouter здесь не нужны) | Готовый текст на запись |
| 3 | Отправляет сообщение в Telegram | Telegram Bot API (тот же токен и прокси, что уже настроены у бота, из `.env`) | Сообщение доставлено |
| 4 | Ставит `remindedAt = now()` этой записи | Postgres (Prisma) | Защита от повторной отправки при повторном запуске сегодня |
| 5 | Печатает отчёт (отправлено / пропущено / ошибки) | Консоль | Отчёт, как в образце выше |

## 6. Как я это запускаю

Руками до команды — ничего особого, база уже наполняется через бота как обычно.

Команда:
```
/remind
```
(под капотом — `cd project/manager/remind && npm run start`, без аргументов, всегда «на завтра»).

## 7. ✅ Мой DoD

- [ ] Запускается одной командой `/remind` (или `npm run start` в `manager/remind/`).
- [ ] В консоли печатается отчёт с разбивкой «отправлено / пропущено / ошибки», как в образце.
- [ ] Реальное тестовое сообщение приходит в мой тестовый Telegram-чат (проверяю глазами в Telegram).
- [ ] Повторный запуск в тот же день НЕ шлёт дубликат тому, кому уже напомнили (проверяю: запускаю дважды подряд, второй раз — 0 отправлено).
- [ ] Запись без `telegramChatId` (с сайта) не роняет скрипт — попадает в «пропущено» с понятной причиной.
- [ ] Отработало на моих тестовых записях в `Booking` за отведённое время.

## 8. Что делаем за 40 минут / что точно не делаем сегодня

**Делаем:**
- 2 новых поля в схеме `Booking` (`telegramChatId`, `remindedAt`) + `db:push`.
- Прокидываю `chatId` в момент, когда бот создаёт запись через `create_booking` (сейчас этот инструмент не знает, из какого чата его вызвали — небольшая, но реальная правка в `openrouter.ts`/`tools.ts`/API).
- Сам скрипт напоминаний (`manager/remind/`) + скилл `/remind`.

**Точно не делаем сегодня:**
- Напоминания для записей с сайта (`/book`) — там нет Telegram-личности клиента; это отдельная задача (SMS/WhatsApp — новый платный сервис, сознательно не беру).
- Автозапуск по расписанию (каждое утро само) — сегодня только ручной запуск.
- Настраиваемое окно напоминания («за день» жёстко в коде, не «за 2 часа» или «за неделю» на выбор).
- Ретраи при сбое отправки — просто попадает в «ошибки» отчёта, руками разбираешься.

## 9. Что доделать между воркшопами

- Автозапуск: systemd timer на сервере, который сам дёргает `/remind` каждое утро (например, в 9:00).
- Настраиваемое окно напоминания (переменная в `.env`, не «завтра» жёстко).
- Подумать над каналом для клиентов с сайта — например, собирать Telegram при записи через `/book`, если клиент захочет.

## 10. Где может сломаться

1. **У записей, сделанных через бота ДО сегодняшнего изменения схемы, `telegramChatId` будет пустым** (поле новое, задним числом не заполнится) — такие уедут в «пропущено», это ожидаемо, не баг сегодняшней сборки.
2. **Telegram откажет в отправке**, если клиент заблокировал бота или чат недействителен — попадает в «ошибки» отчёта, весь скрипт не падает (по одной записи — graceful, как в `/transcribe`).
3. **Часовой пояс**: «завтра» считается по времени сервера (UTC) — если реальный часовой пояс салона другой, у записей на границе полуночи «завтра» может немного съехать.

## 11. Персданные

В `Booking` — реальные ФИО и телефон клиента, а с сегодняшними полями ещё и `telegramChatId`. Сейчас у тебя только тестовые данные — подтвердил это сам. Что НЕ коммитим и вперёд: любые логи/файлы/дампы с реальными ФИО, телефонами или `telegramChatId` — сам код скрипта (шаблон сообщения, запросы к БД) данных не содержит и коммитить его безопасно.
