# /transcribe — расшифровка и осмысление записей

Обёртка над готовым пайплайном в `./project/manager/transcribe/` (Node.js/TypeScript, AssemblyAI + OpenRouter). Вся логика уже реализована в `src/*.ts` — этот скилл **не пишет код заново**, а объясняет, как его правильно запустить в зависимости от того, что попросил пользователь.

## Два режима

### Режим А — без аргументов: пачка из recordings/
Пользователь говорит что-то вроде: «расшифруй, что есть», «прогони /transcribe», «обработай записи» — без указания конкретного файла.

Выполни:
```bash
cd project/manager/transcribe
npm run start
```

Поведение (уже реализовано, просто знай, чего ожидать):
- Берёт ВСЕ аудио/видео файлы из `recordings/` (расширения: mp3, wav, m4a, ogg, oga, flac, aac, wma, mp4, mov, avi, mkv, webm).
- Каждый успешно обработанный файл переносится в `to_delete/` — **только после** успеха.
- Файл, на котором обработка упала (сбой AssemblyAI/OpenRouter), остаётся в `recordings/` нетронутым — можно почитать причину и перезапустить.
- `recordings/` пуст — печатает человеческое сообщение и завершается без ошибки (это не падение).

### Режим Б — с путями: конкретные файлы
Пользователь называет конкретный файл или несколько: «расшифруй ~/Downloads/zoom.m4a», «обработай эти два созвона: ...».

Выполни:
```bash
cd project/manager/transcribe
npm run start -- "<путь1>" "<путь2>"
```
Пути передавай **в кавычках** (могут содержать пробелы) — по одному аргументу на файл. Скрипт сам разворачивает `~` и относительные пути.

Поведение:
- Работает с файлами где угодно на диске, не только внутри проекта.
- Исходник НЕ трогает вообще: не двигает, не переименовывает, не удаляет — независимо от успеха или неудачи.
- Файла нет по указанному пути или расширение не поддержано — печатает понятную строку и переходит к следующему файлу (не падает).

## Результат — одинаково в обоих режимах

- Один `.md`-файл в `./project/manager/transcribe/ready/`: расшифровка → саммари (5–7 пунктов) → сводная таблица задач (столбцы: `# | Задача | Ответственный | Срок | Основание — цитата из расшифровки`). Таблица ничего не выдумывает: нет срока — «срок не задан», нет исполнителя — «не назначен», без дословной цитаты строки быть не должно.
- Имя результата = имя исходника (расширение меняется на `.md`); если удалось определить дату записи (из имени файла или медиа-метаданных через `ffprobe`, если он установлен) — добавляется префикс `ГГГГ-ММ-ДД_` (не дублируется, если такой префикс уже есть в имени). Дата не определилась — это не ошибка, просто нет префикса.
- Имя в `ready/` уже занято — файл не затирается: добавляется суффикс ` (2)`, ` (3)`… и об этом явно сообщается.
- Обработано несколько файлов за один запуск — в конце печатается краткий отчёт: сколько расшифровано, что и почему упало.
- Сбой внешнего сервиса (нет ответа / лимит / кривой вход) — понятная строка в консоли, никогда сырой стектрейс.
- Ключи и адреса сервисов берутся только из `./project/bot_administrator/.env` (`ASSEMBLYAI_API_KEY`, `ASSEMBLYAI_BASE_URL`, `OPENROUTER_API_KEY`, `OPENROUTER_BASE_URL`) — в коде не хардкожены.

## После каждого запуска (в т.ч. пустого)

`./project/manager/transcribe/stats.json` обновляется автоматически самим скриптом — ничего дополнительно делать не нужно. Содержит только цифры и даты (сколько ждёт в `recordings/`, сколько готово в `ready/`, их даты из префиксов имён, время обновления) — без текста расшифровок и персональных данных, файл предназначен для коммита в репозиторий.

## Если что-то пошло не так

Не переписывай интеграцию с AssemblyAI/OpenRouter заново — она уже реализована и протестирована (`src/transcribe.ts`, `src/analyze.ts`, `src/dateDetect.ts`, `src/errors.ts`). Если реальная ошибка не укладывается в существующую обработку — почини точечно, не переписывай пайплайн с нуля.
