# Архитектура

## Части системы

- **Next.js (App Router, TypeScript)** — единое приложение: и фронтенд, и бэкенд (API-роуты) в одном процессе.
  - `/book` — публичная страница записи: выбор услуги → мастера → даты и времени → контакты.
  - `/admin` — админка за паролем (cookie `admin_auth`, сверяется с `ADMIN_PASSWORD` из `.env`): записи, услуги, команда.
  - `/api/*` — REST-эндпоинты (`services`, `masters`, `availability`, `bookings`), которыми пользуются страницы и которые можно дёргать снаружи.
- **PostgreSQL** — поднимается локально через `docker-compose.yml`, том `proservice-db-data` хранит данные между перезапусками.
- **Prisma** — ORM и миграции (`prisma/schema.prisma`), плюс `prisma/seed.ts` для тестовых данных.

## Как части общаются

```
Браузер → Next.js (страницы + /api/*) → Prisma Client → PostgreSQL (Docker)
```

Страницы (`/book`, `/admin`) и API-роуты работают в одном приложении и напрямую вызывают Prisma — отдельного backend-сервиса нет. Внешние потребители (боты, MCP, интеграции с воркшопов) обращаются к `/api/*`.

## Модель данных

`Service` (услуга) ↔ `Master` (мастер) — связаны через `MasterService` (many-to-many). У мастера есть `WorkingHour` (график по дням недели). `Booking` (запись) ссылается на услугу и мастера, хранит интервал `startAt`–`endAt` и статус (`CONFIRMED` / `CANCELLED` / `DONE`).

## Ключевые технические решения

- **Слоты считаются на лету, не хранятся.** `src/lib/availability.ts` берёт график мастера на нужный день недели и вычитает пересечения с активными бронями — свободное время не материализуется в БД.
- **Защита от двойной записи — на уровне API.** `POST /api/bookings` перед созданием брони ищет пересечение по времени среди не отменённых записей того же мастера и возвращает `409`, если конфликт есть (гонки возможны, но для учебного проекта это осознанно упрощено).
- **Админка — простой пароль в cookie, не полноценная авторизация.** Это осознанное упрощение под учебные цели; в `.env.example` это явно прокомментировано.
- **Один универсальный движок вместо готового домена.** Схема нейтральна («услуга + мастер + слот + запись»), а под конкретный домен (салон, автосервис, репетитор) переодевается через `seed.ts` — не через код.
- **Docker только для БД**, само приложение запускается локально через `npm run dev` — меньше инфраструктуры для учебных целей.
